2 ЗАВДАННЯ
     
     Необхідно розробити front-end частину програмної системи. Ця частина системи повинна підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий — для адміністраторів (відповідно до ролей користувачів вашої системи). Користувацький інтерфейс та інтерфейс адміністрування повинні підтримувати інтернаціоналізацію та локалізацію, а саме, забезпечувати: підтримку української на англійської мов сайту, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту тощо. Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи, створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань.


     3 ОПИС ВИКОНАНОЇ РОБОТИ
       
     AgroSense – це комплексна IoT-система для безперервного моніторингу та автоматизованого управління мікрокліматом у теплицях. Головна мета системи – оптимізація врожайності, економія ресурсів (електроенергії, води) та мінімізація впливу людського фактору.
     Система складається з апаратного забезпечення (датчики температури, вологості, освітленості, а також актуатори: насоси, обігрівачі, вентилятори), серверної частини та сучасного клієнтського web-застосунку. 
     Для закладання фундаменту архітектури клієнтського додатка використовувався підхід Generative AI з подальшим глибоким рефакторингом.
     Інструмент ШІ: Google Gemini
     Версія: 1.5 Pro
     Мета використання ШІ: Генерація базової структури проекту, налаштування глобального стану, системи маршрутизації та базової інтеграції WebSockets для IoT системи AgroSense.
     Промпт: "Act as an expert Frontend Developer. Design and generate a modern React SPA for an IoT greenhouse management system called AgroSense. Use Vite, Tailwind CSS v4, and React Router v6. Implement state management using Zustand, separating stores for auth, IoT telemetry, and notifications. Integrate Socket.io-client for real-time telemetry and actuator updates via a headless 'GlobalSocket' component. Use Recharts for data visualization and react-i18next for localization. Ensure an optimistic UI approach for hardware toggling."
     Внесок автора: Проєктування бізнес-логіки, розробка UML-моделей, інтеграція з реальним бекендом, адаптація компонентів під специфічні відповіді бази даних, ручне тестування та налагодження WebSockets, а також налаштування адаптивного UI/UX.
     В якості ядра фронтенду обрано React.js, а збірка проекту здійснюється за допомогою інструменту Vite. На відміну від застарілого Create React App, побудованого на Webpack, Vite використовує нативні ES-модулі браузера під час розробки. Це сучасне рішення забезпечує миттєве завантаження локального сервера (зазвичай менше ніж за 300 мс) та надзвичайно швидке оновлення модулів (Hot Module Replacement). Під час білда для продакшену Vite використовує Rollup, генеруючи високооптимізовані та мініфіковані бандли, що позитивно впливає на загальну продуктивність застосунку.
     Як продемонстровано на UML Діаграмі компонентів (Рис. 1. Дод. Б), стан додатку повністю ізольовано від візуальної частини (UI) за допомогою бібліотеки Zustand. Головною перевагою цього підходу є те, що Zustand дозволяє створювати незалежні слайси стану, такі як useIotStore чи useAuthStore, без необхідності огортати весь додаток у складні Provider-дерева, як це робить Redux. Це значно спрощує типізацію та радикально зменшує кількість шаблонного коду. Функції мутації в Zustand синхронізуються з подіями WebSocket. Оновлення масиву об'єктів у пам'яті миттєво викликає ререндер виключно тих React-компонентів, які безпосередньо "підписані" на ці конкретні дані, забезпечуючи високу реактивність інтерфейсу.
     Весь інтерфейс побудовано за допомогою фреймворку Tailwind CSS. Це інженерне рішення полягає у свідомій відмові від "готових" бібліотек компонентів, таких як Material UI чи Bootstrap, на користь utility-first підходу. Такий крок дозволив створити повністю унікальний дизайн та мінімізувати розмір фінального CSS-файлу завдяки використанню JIT-компілятора, що автоматично видаляє невикористані класи. Водночас це забезпечило абсолютну гнучкість у побудові адаптивних інтерфейсів за допомогою інтуїтивних префіксів для різних розмірів екранів.
     Відповідно до Діаграми прецедентів (Рис. 2. Дод. Б), користувач має можливість змінювати мову інтерфейсу "на льоту" без перезавантаження сторінки. Для реалізації цього функціоналу інтегровано бібліотеку react-i18next. Усі текстові константи акуратно винесено у зовнішні JSON-словники, зокрема для української та англійської мов. У системі також залучено плагін i18next-browser-languagedetector, який аналізує налаштування операційної системи або браузера користувача під час першого візиту і автоматично перемикає додаток на найбільш відповідну мову.
     Для маршрутизації в додатку використовується react-router-dom v6. Інтерфейс архітектурно побудовано навколо системи вкладених маршрутів (<Outlet />), що дозволяє фіксувати глобальні елементи навігації, такі як Sidebar чи Header, і динамічно підмінювати лише контентну частину сторінки. Для забезпечення безпеки імплементовано патерн HOC (Higher Order Components), який захищає маршрути. Компонент ProtectedRoute.jsx відповідає за перевірку наявності валідного токена в useAuthStore і автоматично перенаправляє неавторизованих користувачів на сторінку входу. Зі свого боку, AdminRoute.jsx здійснює додаткову перевірку ролі користувача, суворо обмежуючи доступ до панелі керування.
     Взаємодія з REST API ізольована та централізована у файлі src/api/axios.js. Тут застосовано патерн Interceptor, який одночасно вирішує дві ключові інженерні задачі. По-перше, він забезпечує ін'єкцію токена, автоматично додаючи заголовок Authorization: Bearer <token> до всіх вихідних запитів, що повністю звільняє розробника від ручної передачі токена в кожній окремій API-функції. По-друге, інтерсептор гарантує глобальну обробку помилки 401 Unauthorized. Якщо токен протермінувався або став недійсним, інтерсептор відповідей перехоплює цю помилку на найнижчому рівні, очищає локальне сховище та ініціює примусове розлогінення користувача.
     Інструмент ШІ: Google Gemini
     Версія: 1.5 Pro
      Мета використання ШІ: Реалізація Axios інтерсепторів для автоматичного додавання JWT токенів до API-запитів та глобальної обробки помилок 401 Unauthorized для безшовного керування сесією.
      Промпт: "Create Axios interceptors for a React application. One interceptor should attach a JWT token from localStorage to the Authorization header. The second should catch 401 errors globally, clear the local storage, and reject the promise to handle session expiration."
      Внесок автора: Інтеграція інтерсептора з існуючим екземпляром API. Перевірка вилучення токена з localStorage та додавання надійної логіки для очищення даних користувача разом із токеном для повного скидання стану на стороні клієнта.
     
1. api.interceptors.request.use(
2.   (config) => {
3.     const token = localStorage.getItem('auth_token');
4.     if (token) {
5.       config.headers.Authorization = `Bearer ${token}`;
6.     }
7.     return config;
8.   },
9.   (error) => Promise.reject(error)
10. );
11. 
12. api.interceptors.response.use(
13.   (response) => response,
14.   (error) => {
15.     if (error.response && error.response.status === 401) {
16.       localStorage.removeItem('auth_token');
17.       localStorage.removeItem('user_info');
18.     }
19.     return Promise.reject(error);
20.   }
21. );

     Найбільш критичною частиною системи є безперебійне відображення телеметрії в реальному часі. Цей процес змодельовано на UML Діаграмі діяльності (Activity Diagram) (Рис. 3. Дод. Б). Щоб не прив'язувати WebSocket-підключення до конкретної візуальної сторінки, яка може бути розмонтована при навігації користувача, було створено спеціальний компонент GlobalSocket.jsx. Це так званий "Headless" компонент – він  повертає null і не генерує жодної HTML-розмітки. Його єдина, але надважлива мета – існувати  на рівні глобального UserLayout і керувати життєвим циклом з'єднання socket.io-client. 
     Інструмент ШІ: Google Gemini
      Версія: 1.5 Pro
      Мета використання ШІ: Створення "headless" React компонента, який управляє глобальним WebSocket з'єднанням та слухачами без впливу на візуальне дерево DOM.
      Промпт (Prompt): "Create a headless React component called GlobalSocket that manages a Socket.io client connection. It should connect when the user is authenticated and emit 'join_greenhouse' for each greenhouse the user owns. Listen for 'telemetry_update' and 'actuator_update' events and dispatch actions to the Zustand store."
      Внесок автора: Інтеграція компонента в головний макет маршрутизації (UserLayout), щоб гарантувати його монтування лише при дійсній авторизації. Коригування масивів залежностей у хуках useEffect для запобігання витокам пам'яті та нескінченним ререндерам під час HMR.

1. useEffect(() => {
2.   if (!isAuthenticated) {
3.     socket.disconnect();
4.     return;
5.   }
6. 
7.   if (!socket.connected) socket.connect();
8. 
9.   // Приєднання до кімнат (Room Isolation)
10.   greenhouses.forEach(gh => socket.emit('join_greenhouse', gh.id));
11. 
12.   const handleTelemetryUpdate = (data) => updateRealtimeTelemetry(data);
13.   socket.on('telemetry_update', handleTelemetryUpdate);
14. 
15.   return () => {
16.     socket.off('telemetry_update', handleTelemetryUpdate);
17.   };
18. }, [isAuthenticated, greenhouses]);

19.
     Для відмальовки історії показників у системі застосовано бібліотеку Recharts (<AreaChart />). Оскільки масив історії оновлюється безпосередньо в реактивній пам'яті Zustand, графіки плавно перемальовуються, додаючи нові точки в реальному часі без жодної необхідності перезавантаження даних чи додаткових запитів до бекенду.
     Що стосується керування фізичними пристроями, як показано на UML Діаграмі станів (State Diagram) (Рис. 4. Дод. Б), застосовується підхід оптимістичного UI. При кліку на тумблер обігрівача чи насоса фронтенд тимчасово блокує цей елемент, переводячи його у стан завантаження, та відправляє PATCH-запит через Axios. Лише після успішної відповіді від сервера (200 OK) система остаточно оновлює стан у глобальному сховищі. Якщо ж мережевий запит з якихось причин провалиться, інтерфейс автоматично зробить відкат (Rollback) до попереднього стану і виведе користувачу відповідне сповіщення про помилку.
     Інструмент ШІ: Google Gemini
      Версія: 1.5 Pro
      Мета використання ШІ: Реактивне оновлення глобального стану Zustand при отриманні подій WebSocket ('telemetry_update', 'actuator_update') від бекенду.
      Промпт (Prompt): "Write a Zustand store function `updateRealtimeActuator` that takes a payload with actuatorId, currentState, and value. It should map through the existing actuators array, find the matching ID, parse boolean states, round the numerical power value, and return the updated state."
      Внесок автора: Вдосконалення логіки парсингу значень для забезпечення послідовного застосування Math.round() у всіх оновленнях, щоб уникнути багів інтерфейсу з числами з плаваючою комою. Відображення змінних корисного навантаження бекенду на суворі очікування фронтенду.
     
1. updateRealtimeActuator: (data) => {
2.   set((state) => ({
3.     actuators: state.actuators.map(actuator => {
4.       if (actuator.id === data.actuatorId) {
5.         // Парсимо стан та заокруглюємо потужність до цілих чисел
6.         const isStateOn = data.currentState === true || data.currentState === 'true';
7.         const actualValue = data.value !== undefined ? Math.round(Number(data.value)) : actuator.value;
8.         
9.         return { ...actuator, state: isStateOn, value: actualValue };
10.       }
11.       return actuator;
12.     })
13.   }));
14. }



       
     4 ВИСНОВКИ
       
     У ході виконання лабораторної роботи було успішно розроблено фронтенд-архітектуру системи AgroSense, яка демонструє сучасний підхід до створення комплексних IoT-застосунків. Використані рішення дозволили забезпечити високу продуктивність, чуйність інтерфейсу та масштабованість системи. Чіткий розподіл ролей реалізовано через захищені маршрути та механізми перехоплення запитів (interceptors), що забезпечує контроль доступу та стабільну взаємодію з серверною частиною.
     Взаємодія компонентів побудована на основі гібридного підходу із використанням REST API та WebSockets, що дозволяє отримувати оновлення в режимі реального часу без надмірного навантаження на клієнтський пристрій. Використання легких state-менеджерів і компонентного підходу забезпечило зручне керування станом застосунку та спростило інтеграцію телеметричних даних.
     Завдяки такій архітектурі інтерфейс системи, включаючи елементи керування, графіки та сповіщення, оперативно реагує на зміни стану мікроклімату в теплиці, забезпечуючи користувачу стабільну та інтуїтивно зрозумілу взаємодію з системою в реальному часі.
