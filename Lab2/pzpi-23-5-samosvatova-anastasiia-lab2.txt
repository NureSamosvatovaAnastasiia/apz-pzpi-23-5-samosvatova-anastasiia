2 ЗАВДАННЯ
     
     Необхідно розробити мобільний програмний застосунок для будь-якої поширеної на сьогодні мобільної платформи. Мобільний застосунок повинен бути частиною системи і повинен взаємодіяти з нею. Звіт повинен містити опис прийнятих інженерних рішень. У ньому повинна бути показана будова мобільного застосунку та його взаємодія з іншими частинами системи.
     

       
     3 ОПИС ВИКОНАНОЇ РОБОТИ
       
     Мобільний застосунок AgroSense Mobile є клієнтською частиною програмно-апаратного комплексу для автоматизації та моніторингу тепличних господарств. Його головне завдання – надати користувачам (фермерам, агрономам, адміністраторам) зручний інтерфейс для віддаленого керування IoT-пристроями (сенсорами та актуаторами), перегляду аналітики та отримання критичних сповіщень у режимі реального часу. Застосунок розроблено з використанням кросплатформного фреймворку .NET MAUI (Multi-platform App UI), що дозволяє генерувати нативні збірки для Android та iOS з єдиної кодової бази мовою C#. Функціональні можливості системи та ролі користувачів детально проілюстровані на Діаграмі прецедентів (Use Case Diagram) (Рис. 1. Дод. Б).
     Архітектура всього комплексу побудована за принципом клієнт-серверної взаємодії. Мобільний застосунок виступає виключно як шар представлення (Presentation Layer) і не виконує важких обчислень чи прямого доступу до бази даних. Ця взаємодія структурно зображена на UML Діаграмі компонентів (Component Diagram) (Рис. 2. Дод. Б).
     Для зв'язку використовується протокол HTTP/HTTPS. Усі запити захищені за допомогою JWT-токенів, які передаються в заголовку Authorization. Послідовність взаємодії клієнта з сервером, від авторизації до керування актуатором, покроково відображена на UML Діаграмі діяльності (Activity Diagram) (Рис. 3. Дод. Б).
     В основу архітектури покладено патерн MVVM (Model-View-ViewModel). Логічний поділ на шари та простори імен Views, ViewModels, Models, Services показано на UML Діаграмі пакетів (Package Diagram) (Рис. 4. Дод. Б).

     Централізована робота з мережею (ApiService). Створено базовий клас, який інкапсулює логіку роботи з HttpClient. Інженерне рішення: Метод AddAuthorizationHeaderAsync автоматично дістає JWT зі сховища і додає його до кожного запиту. Також реалізовано метод PatchRawAsync для точкового керування IoT. Приклад коду (Services/ApiService.cs):
     Назва інструменту ШІ: Google Gemini 1.5 Pro
     Промпт для створення коду: "Write an ApiService class in C# for a .NET MAUI app. The service should encapsulate an HttpClient instance. Implement a method that asynchronously retrieves a JWT token from SecureStorage and attaches it as a Bearer token to the DefaultRequestHeaders. Also, provide a generic method for sending PATCH requests (PatchRawAsync) with JSON content, returning the raw HttpResponseMessage."
     Внесок автора: Реалізовано метод PatchRawAsync для взаємодії з IoT та додано безпечне зчитування токену з SecureStorage.
     
1. private async Task AddAuthorizationHeaderAsync()
2. {
3.     var token = await SecureStorage.Default.GetAsync("jwt_token");
4.     if (!string.IsNullOrEmpty(token))
5.     {
6.         _httpClient.DefaultRequestHeaders.Authorization = 
7.             new AuthenticationHeaderValue("Bearer", token);
8.     }
9. }
10. 
11. public async Task<HttpResponseMessage> PatchRawAsync(string endpoint, object data)
12. {
13.     await AddAuthorizationHeaderAsync();
14.     var jsonContent = JsonContent.Create(data);
15.     return await _httpClient.PatchAsync(endpoint, jsonContent);
16. }
17.

     Асинхронне фонове оновлення (Polling) та Оптимістичний UI. Для модуля "Сповіщення" (Notifications) використано механізм фонового опитування сервера за допомогою IDispatcherTimer.. Інженерне рішення: Оптимістичне оновлення – статус прочитання миттєво змінюється в локальній пам'яті (UI реагує за мілісекунди), а HTTP-запит відправляється у фоні. Приклад коду (ViewModels/NotificationsViewModel.cs)
     Назва інструменту ШІ: Google Gemini 1.5 Pro
     Промпт для створення коду: "Write a RelayCommand method in C# for a .NET MAUI ViewModel that marks a notification as read. Implement the 'Optimistic UI' pattern: first, immediately update the 'IsRead' property of the notification in the local ObservableCollection (triggering a UI refresh by removing and re-inserting the item), and then perform the asynchronous network call to the NotificationService to sync the state with the server. Wrap the network call in a try-catch block."
     Внесок автора: Реалізовано миттєве оновлення списку в UI за допомогою маніпуляцій з ObservableCollection до отримання відповіді від сервера.
     
1. [RelayCommand]
2. private async Task MarkAsReadAsync(Notification notification)
3. {
4.     if (notification == null || notification.IsRead) return;
5. 
6.     // 1. Оптимістичне оновлення UI (Миттєва реакція)
7.     notification.IsRead = true;
8.     var index = Notifications.IndexOf(notification);
9.     if (index >= 0) {
10.         Notifications.RemoveAt(index);
11.         Notifications.Insert(index, notification);
12.     }
13. 
14.     // 2. Фонова відправка на сервер
15.     try {
16.         await _notificationService.MarkAsReadAsync(notification.Id);
17.     } catch (Exception ex) {
18.         // Логування помилки
19.     }
20. }

     Оптимізація компіляції (Trimming). Через використання патерну MVVM (який покладається на рефлексію для Data Binding), в режимі Release було змінено налаштування оптимізатора (Linker), щоб уникнути випадкового видалення використовуваного коду. У файлі .csproj було налаштовано <PublishTrimmed>false</PublishTrimmed> та генерацію Debug Symbols для стабільності на Android.
     Під час розробки програмного забезпечення та підготовки цієї документації використовувались технології штучного інтелекту як допоміжний інструмент.
     Назва інструменту ШІ та версія: Google Gemini 1.5 Pro.
     Мета використання ШІ: Генерація базового шаблонного коду для .NET MAUI, допомога у побудові структури патерну MVVM (Model-View-ViewModel), генерація класів моделей (DTO) на основі JSON-відповідей та створення оптимізованих фрагментів XAML-розмітки.
     Промпт для створення коду (англійською мовою): "Act as a Senior .NET MAUI Developer. Generate MVVM C# code, backend communication services, and XAML views for an IoT Greenhouse mobile application. Use CommunityToolkit.Mvvm for logic and implement a centralized ApiService for REST communication."
     Внесок автора: Згенеровані ШІ фрагменти коду були критично проаналізовані, перевірені та протестовані в середовищі Visual Studio. Було власноруч модифіковано логіку взаємодії з REST API відповідно до реальної архітектури серверної частини, виправлено проблеми з Data Binding та оптимізацією (Trimming/AOT) при збірці Release-версії для Android. Також було самостійно інтегровано кастомний механізм локалізації UI та оптимістичного оновлення стану застосунку.


       
     4 ВИСНОВКИ
       
     У ході виконання лабораторної роботи було успішно розроблено та реалізовано повноцінний мобільний застосунок для взаємодії з IoT-пристроями. Обраний стек технологій, .NET MAUI та CommunityToolkit.Mvvm, а також використані архітектурні рішення, такі як dependency injection, єдина точка роботи з API та оптимістичний UI, дозволили створити масштабований, модульний і продуктивний мобільний клієнт. Завдяки низькій зв’язності компонентів застосунок легко адаптується до нових вимог і може бути розширений без необхідності масштабного рефакторингу існуючого коду, що особливо важливо при додаванні нових IoT-пристроїв або функціональних можливостей. Отриманий результат демонструє ефективність використаного підходу та підтверджує доцільність застосування сучасних інструментів і патернів розробки для створення кросплатформених мобільних рішень.
